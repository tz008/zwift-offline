# 单机机器人配置页

## Intent

用户要求在 Windows 启动窗口选择“本机单机”时增加可配置页，设置上一轮确认已支持的 Solo Blob 跟骑机器人。单机区域提供“机器人配置”入口及当前状态，独立配置页允许保存开关、人数、队形和轮换设置，随后启动游戏即读取保存结果。

本请求已经授权实现和本地构建；沿用现有中文界面及 Tkinter。现有未提交的 `.github/workflows/pyinstaller.yaml`、`.gitignore`、`standalone.py` 与 `windows_launcher.py` 为其他工作改动，继续保留。

## Boundaries & Constraints

沿用服务端现有 `storage/solo_blob.txt` JSON，保留正常跟骑算法、游戏内聊天指令、UAC、网络及退出恢复机制。散开采样位置因人数或已有高级参数不足时，沿用既有列队布局及安全默认间距，保证所选机器人数量并记录日志。配置页只在单机模式提供入口，会话进行时不可编辑。不增加外部依赖。GUI 配置应使用轻量的标准库辅助模块，不为打开页面而导入并启动服务端。

保存仅更新所提供的选项，保留未知的手工配置键；绑定玩家的规则匹配服务端实际选择的单机 profile，缺少 profile 时回退玩家 1。默认值匹配 `solo_blob.DEFAULT_CONFIG`。配置读取或保存失败显示明确中文错误，不能悄悄覆盖损坏配置。写入使用同目录临时文件和原子替换，以 ASCII 转义 JSON 兼容引擎在 Windows 使用的默认编码；关闭、取消和重置草稿都不写盘。

## I/O & Edge-Case Matrix

| 场景 | 预期行为 |
| --- | --- |
| 无配置文件 | 显示默认关闭、8 人及原算法默认选项；只打开页面不创建文件 |
| 已有配置 | 回显受支持选项；保存保留未在界面提供的键 |
| 启用并保存 | 保存 enabled 与 1–30 人，以及队形/轮换设置；单机启动前生效 |
| 关闭并保存 | 保存关闭状态，启动时不生成跟骑机器人 |
| 输入非法、NaN/Infinity、数量越界 | 指明具体字段，保留页面及原文件 |
| 已有手工参数超出 UI 编辑范围但引擎可接受 | 能回显且不因新编辑范围阻止原有单机启动 |
| 高人数、窄散开队形与较大横距组合 | 输入作组合校验；已有高级参数仍令散开位置不足时，运行时自动使用列队布局，保证人数并避免启动失败 |
| 切换队形后存在失效草稿 | 不适用字段沿用已保存参数；活动字段出错时显示所在页供修正 |
| 单机 profile 位于非 1 目录或扩展字段包含中文 | 绑定实际玩家，保存后引擎仍可读取并生成所选人数 |
| JSON 损坏、结构不符或权限失败 | 提示文件问题，不静默重置或覆盖 |
| 取消、标题栏关闭、恢复默认草稿 | 不改变原配置；恢复默认须点击保存才生效 |
| 切换联机模式或会话运行 | 联机不显示入口；运行时入口禁用；原启动流程正常 |

## Code Map

- `windows_gui.py`：单机区域、启动按钮、忙碌状态、配置弹窗及反馈。
- `windows_bot_config.py`：新增轻量默认值、校验、加载和原子保存。
- `solo_blob.py`：实际消费配置，提供默认值；增加散开容量检查及安全列队处理。
- `tests/test_windows_gui.py`：已有隐藏 Tk 回归测试。
- `standalone.spec`：GUI 的静态导入自动纳入现有单文件构建。

## Spec Change Log

2026-11-12 独立审查发现规格中“单机固定为玩家 1”的假设与服务端选择既有 profile 的行为不符，改为匹配实际单机身份；保留原页面结构、原子保存及取消语义。边界审查复现合法散开参数组合令引擎槽位不足，补充组合校验；验收审查复现 UTF-8 中文扩展字段被引擎按 Windows 默认编码读坏，补充 ASCII JSON 兼容写入。其余修复包含自然散开禁用无效位置交换参数、隐藏无效草稿不阻塞保存、深层坏 JSON 的错误包装，以及已有有效手工参数不被新增编辑范围阻止启动。均在同一机器人配置目标内修复。

最终复核进一步实证：原本正常的 8 人手工配置保留 `scatter_gap=4` 后增加至 30 人，即使通过 GUI 半宽规则，实际采样位置仍可能不足。补充最小运行时保护，在索引选择之前检查本轮真实容量，不足时走原有列队布局；只对该保护路径使用安全默认队列参数，保留正常算法和手工扩展字段。
