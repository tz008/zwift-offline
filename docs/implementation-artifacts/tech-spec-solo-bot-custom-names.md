# 单机机器人自定义名称

## Intent

在上一轮已完成的单机机器人配置页中，新增“自定义名称”标签页，允许用户逐个设置跟骑机器人的显示名称。名称随现有配置保存并由真实机器人资料消费，中文、英文和带空格名称均可使用。用户已经要求继续扩展现有功能，保留上一轮及其他工作中的未提交更改。

## Boundaries & Constraints

只扩展 Solo Blob 机器人配置，不改普通 bots、RoboPacers、网络及系统配置。名称使用 `storage/solo_blob.txt` 的可选 `custom_names` 字符串数组，默认空数组；沿用 ASCII 转义 JSON、未知字段保留和原子保存。GUI 不导入服务端。每行对应固定序号机器人，空行继续使用原随机名称；最多 30 行，每个名称最多 40 个 Unicode 字符，去除首尾空白，拒绝控制字符和非法代理码点。

机器人数量减少时保留暂未使用的名称，增加时按原序号重新使用。换阵容、重启和新骑行时保留对应序号的名称，装备及其他参数继续原流程。单个名称完整写入资料的姓字段、名字字段留空，保证单段中文名字及空格名称不会被原有默认序号污染；手势反馈使用完整名称。未提供名称时资料创建行为保持不变。

取消或关闭不写盘，恢复默认只清空草稿；保存后随下次启动生效，会话运行期间保持配置入口禁用。旧配置无 `custom_names` 时自动使用默认值，已有手工高级配置及本地玩家选择规则继续保留。

## I/O & Edge-Case Matrix

| 情况 | 行为 |
| --- | --- |
| 无名称配置 | 名称页空白，服务端继续使用原随机名字 |
| 中文/英文/空格名字与中间空行 | 保存回显不丢位置；指定机器人使用名称，空行随机 |
| 名称数少于/超过当前人数 | 少的随机补齐，多的保留但暂不使用 |
| 保存后换阵容、开始新骑行 | 名称按机器人序号保留 |
| 空白文本或恢复默认后保存 | 清空自定义名称，恢复原随机命名行为 |
| 超过30行、名称超过40字符、控制字符或坏结构 | 提示具体名称行，自动切到名称页，不更改文件 |
| 取消、关闭、恢复默认但未保存 | 原文件不变 |
