# 骑行中实时修改机器人配置

## Intent

用户要求修改机器人配置实时生效，包括正在骑行中。沿用当前单机配置页，允许本机服务已经运行时编辑，保存开关、人数、名称、队形及节奏后由当前服务自动应用；无需重启游戏、结束活动或输入聊天指令。保留上一轮功能及其他工作中的未提交修改。

## Boundaries & Constraints

仍使用 `storage/solo_blob.txt`、原子保存和现有配置校验，不新增网络接口或依赖。配置页只服务本机单机模式；网络模式选择等其他运行控件继续冻结。启动/授权、停止/还原及退出期间禁止新开机器人编辑，服务真正运行后可以打开；服务在编辑时结束，保存仍能留作后续配置，提示按实际状态更新。

服务每 0.5 秒检查配置，正常情况下约 1 秒内应用。配置文件变动识别采用纳秒时间/尺寸及文件身份等可靠签名，兼容 GUI 原子替换。保存相同配置不应重建车队。有效更新完成构造后再替换，失败保留原有车队和轨迹并记录具体日志，禁用/删除文件则及时移除旧机器人。旧配置默认值、未知高级参数及自定义名称语义保留。

正在骑行时更新保留相同玩家的 Trail 和必要运动状态，不等待重新积累轨迹；关闭再开启时可用近期玩家轨迹迅速恢复，缓存有明确数量上限并遵守原有轨迹过期规则。修改名称或人数生成新的机器人 ID，使客户端重新请求资料；布局/节奏等不涉及资料的修改尽量保留身份和装备。更新后注册表只包含当前机器人，避免残留旧名称或重复人数。玩家实际活动进度不受影响。

## I/O & Edge-Case Matrix

| 状态或动作 | 预期行为 |
| --- | --- |
| 单机已运行，打开配置并保存 | 入口可用，约1秒内由正在运行的服务消费，文案说明当前应用 |
| 启动/停止/还原或局域网 | 机器人入口禁用或不显示，保持原会话流程 |
| 改人数/名称/队形/间距/轮换/手势 | 新配置被消费，轨迹和玩家活动持续，不残留旧机器人 |
| 骑行中关闭机器人、稍后开启 | 关闭清空其注册表；开启用近期轨迹恢复 |
| 反复快速保存、相同配置保存 | 最终配置生效，同值不无故更换阵容 |
| 配置损坏或构造失败 | 原车队继续，日志提示；文件修正后可重新应用 |
| 编辑时服务结束或错误 | 页面可取消/保存，无崩溃，保存提示不冒充已实时应用 |
| 取消或输入不合法 | 文件和当前车队不变 |

## Code Map

- `windows_gui.py`、`windows_session.py`：单机模式、启动/运行/还原状态、会话事件和机器人配置反馈。
- `solo_blob.py`：配置文件监测、manager 注册表、轨迹、机器人资料生成及布局。
- `windows_bot_config.py`：沿用已有保存和输入校验。
- `tests/test_solo_blob_live_config.py`、`tests/test_windows_gui.py`、`tests/test_windows_session.py`：真实 manager/状态合成与文件更新、隐藏 Tk 和会话事件验证；保留原配置测试。
